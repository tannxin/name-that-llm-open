# E42 双 T4 无评分部署探针

2026-11-14。E42 的固定 E24+E42 五折融合通过预登记离线门槛，但尚未通过 Kaggle 部署门槛。本文件只规划工程验证，不改变训练、类别、融合权重或评估协议，也不使用 OOF、保留集或公榜选部署参数。

## 已知资源边界

- 固定 `Qwen/Qwen3-14B-Base` revision `0b0bd3732e2c374d483664439ea334928b65f304` 的八个 BF16 权重分片共 29,536,665,640 字节；完整运行需逐项核验 15 个文件。训练与 3090 资源探针使用 NF4 双量化、FP16 计算、Transformers 4.51.3、PEFT 0.15.2、Accelerate 1.6.0、bitsandbytes 0.45.5 和 Torch 2.6.0。
- 3090 资源探针从重新加载底座与折 1 adapter 开始计量：推理峰值保留显存 17.20 GiB，4,000 条训练侧重复文本约 13 分钟。完整五折的验证推理峰值也为 17.20 GiB。这超过单张 T4 的约 15 GiB 可用显存，且 3090 时间不能直接外推到 T4。
- 先前 Kaggle 无评分环境探针实测双 T4 各空闲 14,912 MiB、`/kaggle/working` 可用约 19.5 GiB；已核验的 52-wheel 离线环境可安装并在两卡做微型 NF4 前向。工作盘容不下再复制一份约 29.5 GB 的底座，应从只读模型输入加载，临时盘只存小型环境、日志与输出。

## 顺序与停止条件

1. **CPU 完整性门槛。**先用不加载 GPU、Internet off 的私有 Notebook 检查 Kaggle 官方 QwenLM 14b-base V1 的 15 个必需文件大小与 SHA-256 是否和固定 revision 完全相同。若有差异，停止该模型输入路线；只在能提供逐文件精确私有底座时继续。检查 adapter、分类头、tokenizer 与标签顺序的文件哈希。不要把底座复制到 `/kaggle/working`，也不挂比赛数据。
2. **3090 原始 logits 参考。**在项目 Pod 上用折 1 adapter 和固定底座，对三条折 1 训练侧文本保存 3×18 原始 logits、文本哈希、模型与 adapter 哈希、依赖版本；不读标签或计算准确率。文件留在 Git 忽略区。与 E39 探针相同，任何竞争数据/逐行预测不得进 Git。
3. **双卡加载探针。**复用已通过的 cp313/cu118 离线 wheelhouse，逐 wheel SHA 验证和 `pip check` 后，先用两张真实 T4 的空闲显存设置保守上限。对 `AutoModelForSequenceClassification.from_pretrained` 使用相同 NF4/FP16 配方，并将连续 Transformer 层分配到两卡；`embed_tokens`、末端 norm 与 `score` 分类头位置明确记录。可以仅根据模块大小与空闲显存确定固定分界，不用任何验证分数。加载后断言所有参数、缓冲区和量化模块都在两张 GPU，无 CPU/disk offload，并记录两卡加载及前向峰值。任一卡 OOM、CPU offload、文件不符或非有限 logits 即停止。
4. **数值一致性门槛。**用完全相同的三条训练侧文本、原始回答、`max_length=256`、tokenizer 与 18 类顺序计算 T4 3×18 原始 logits；与 3090 参考逐项比较。沿用 E39 已预先固定的逐项绝对误差 ≤0.05、相对容差 0，且三条文本的 argmax 必须完全一致；记录实际最大绝对/相对误差。分卡可能改变 FP16 舍入，不能把“能加载”视作同一模型行为。若超容差，保留日志并停止，不根据验证标签调分界或重标定。
5. **完整无评分吞吐门槛。**仅在上述通过后，用预先固定的 4,000 条训练侧文本或同分布无标签输入实测批次 1、最长 256 token 的底座+adapter 推理；记录两卡峰值、加载/安装/推理总耗时、可用盘与输出格式。再将既定 E24 分支的加载和推理计入完整流程，在 Kaggle Internet off、T4×2、9 小时会话中留至少 1 小时余量。输出仅为无评分形状/完整性检查，不产生比赛提交文件。

只有 CPU 文件、双卡加载、数值一致性、完整 4,000 行和 E24 联合部署全部通过，才可讨论训练 E42 全量 adapter 与提交。任何通过都不改变既定五折离线结论。E39 的 8B 探针应优先完成，因为它已经具备可复用的 Kaggle 私有资产，且 E42 相对 E39 只增加 0.000463 BA、仅 3/5 折不降；这个比较仅用于工程资源安排，不用于改权或选验证模型。
