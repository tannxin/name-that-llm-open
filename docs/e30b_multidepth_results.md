# E30-B：多深度读出五折结果

审计日期：2026-11-11。按[预登记协议](e30b_multidepth_preregistration.md)，E30-B 在同一 Qwen3-Embedding-8B 基座上固定读取隐藏状态 12、24、36，拼接后接一个 18 类线性头；数据、五折、训练日程和融合权重均未按验证结果调整。本页报告官方开发集 OOF，不是 Kaggle 成绩。[独立审计脚本](../audit_e30b_fivefold_results.py)重新计算结果；[聚合审计 JSON](e30b_multidepth_audit_aggregate.json)保留完整逐折、逐类指标。逐行 OOF、训练数据和模型权重不进入 Git。

## 完整性与效果

五折各有 432 个唯一验证 ID，合并恰覆盖锁定的 2,160 行、120 个开发 prompt 和 18 类；每类 120 行。审计逐行核对 ID、prompt、真值与折号，验证 prompt 跨折隔离，五折 OOF 与汇总文件一致。训练脚本、配置、协议锁、资源报告及报告中的官方模型和数据哈希一致；五折均完成固定的 3 epoch，训练损失与验证 logits 有限，未使用保留的 30 个 prompt 选模。审计未读取隐藏测试答案。

| 固定方法 | 五折 balanced accuracy |
| --- | ---: |
| E24 | 0.425000 |
| E30-A 单路 | 0.353704 |
| E30-B 单路 | 0.432870 |
| E24 + E30-A | 0.448611 |
| E24 + E30-B | **0.457870** |

E24 + E30-B 相对预登记的比较器 E24 + E30-A 增加 **0.009259**，五折 **5/5** 不下降，最差类别 `claude-opus-5` 的召回变化为 **−0.033333**。按 prompt 配对重采样 20,000 次的增量 95% 分位区间为 **[−0.000926, +0.019444]**；同一开发集经过多轮选模，此区间不能替代独立测试。

预登记晋级要求同时满足：增量至少 **+0.010000**、至少 4/5 折不下降、任一类召回下降严格小于 0.05。E30-B 的增量差 **0.000741** 才达到第一项，因此**未通过晋级门槛**。它相对 E24 的固定融合有提升，但不能事后更换预登记比较器。保守地再与未晋级的 E28 固定融合比较时，逐类门槛也未通过。没有因此训练全量部署 adapter 或提交 Kaggle；已确认的最佳公榜仍是 E24 的 **0.434**。

## 资源与运行边界

单折资源试验的 1 epoch 用时 **1,073.29 秒**，4,000 行无标签代理推理用时 **577.16 秒**；训练和推理峰值保留显存分别约 **8.00/14.53 GiB**，计划优化器更新完成率 **97.69%**。五折实际训练墙钟合计 **16,426.15 秒（4.56 小时）**，最高训练峰值约 **8.01 GiB**，最高验证峰值约 **14.53 GiB**。这些值通过预设的单 epoch ≤3,600 秒、三 epoch 推算 ≤10,800 秒、4,000 行推理 ≤10,800 秒、峰值 <22 GiB 和更新完成率 ≥95% 门槛。它们来自服务器 GPU，**尚未证明 Kaggle GPU 上的离线重载、全量 adapter 或完整提交时间**。
