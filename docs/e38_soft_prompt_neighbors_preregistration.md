# E38：无提示 ID 的软同题近邻校正（预登记）

冻结于首次查看 E38 检索或分类结果之前。目标是检验公开高分方案中的提示中心化能否在本赛实际推理输入只有 `id,text` 时成立。[参赛者复盘](https://github.com/PiKa919/kaggle-name-that-llm)提示隐藏测试的同题回答可能只出现 1–8 条，因此同时检验完整验证批次和稀疏批次。E24 的 120 个开发 prompt、五折及 30 个曾用保留 prompt 的边界均不改变；本实验不读保留集或测试回答。官方 `train.csv` SHA-256 固定为 `40a22ce8d88c5f46feb4637a099db815bef5f713ffe53e89dbe1b7b21de77707`；E24 指标及 OOF 文件 SHA-256 分别为 `301463b680bbf83a46bc106ff273e64db853358e131b29c40410a88f8770a557`、`8230d7438eb6c0df7015edc61a54cf880904b85d1f8d599fd549a57e357b4448`。

## 固定的无标签检索

每个外层折只用其训练回答拟合一个词级 TF-IDF：英文停用词去除、小写、1–2 gram、`min_df=2`、`max_features=100000`、`sublinear_tf=True`、L2 归一化。对同一验证批次内的回答计算余弦相似度，排除自身；每行取相似度至少 **0.20** 的最多 **5** 个近邻。分类标签与 `prompt_id` 不进入检索、阈值或近邻权重；原训练折 `prompt_id` 只用于固定分折。近邻的权重为其余弦相似度的平方，归一到和为 1；没有合格近邻则不改该行分数。

先作无标签检索预检，只在结果落盘后用验证 `prompt_id` 作审计：完整批次报告前五近邻的同题精度、覆盖率；稀疏批次报告有至少一个同题候选行的 top-1 同题精度及合格近邻覆盖率。稀疏批次通过每个 prompt 内按 `SHA256("e38:sparse:v1:" + id)` 排序，再按 **1、2、3、4、8** 条依次分为五个 panel；五个 panel 恰覆盖每个 prompt 的 18 条回答一次。候选检索只看 panel 内文本，panel 构造使用 `prompt_id` 仅为模拟不同题目回答被抽样的评估场景。若稀疏 top-1 同题精度低于 **0.60** 或合格近邻覆盖率低于 **0.70**，停止校正评分；不能据预检结果修改检索设置。

## 固定分类规则与晋级

E24 原始 18 类 OOF 分数定义为已归档的 `row_z(E24 E0c) + row_z(RoBERTa) + mean_seed row_z(ModernBERT)`；必须逐行复现已存 E24 预测及 balanced accuracy **0.425000**。对每行，在相同验证批次内使用上述近邻的 E24 分数加权平均 `n_i`，候选分数固定为 `s_i - 0.5 n_i`。这个系数和所有阈值在看到 E38 指标前冻结；不训练融合权重，不使用真实同题均值。完整批次、五个稀疏 panel 均按相同规则评分，并重组成 2,160 行 OOF。

必须同时满足：完整批次相对 E24 BA 至少 **+0.01**、至少 **4/5** 外层折不降、任何类别召回下降 **小于 0.05**；稀疏批次重组成的 BA 不能低于其 E24 原始基线，且必须报告按 prompt 配对 bootstrap 区间。若两种批次结论不同，按较保守者处理。只运行这一组固定候选；不在同一 OOF 上搜索 k、相似度阈值、中心化系数或 panel 划分。

这是 CPU 推理后处理实验，可与独立 GPU 骨干资源预检并行。即使晋级，也要验证 Kaggle 完整隐藏批次内存、耗时与只含 `id,text` 的接口，再准备提交。
