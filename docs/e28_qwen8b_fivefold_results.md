# E28：Qwen3-8B 官方数据五折结果与独立审计

审计日期：2026-11-11。E28 的[预登记协议](e28_qwen8b_fivefold_protocol.md)固定了官方开发集五折、3 epoch、`Qwen/Qwen3-8B` revision `b968826d9c46dd6066d109eabc6255188de91218`、18 类普通交叉熵，以及对 E24 融合**加 1.0 路逐行标准化 E28 logits**。本页仅审计已完成的服务器输出；未重新训练、未使用 30 prompt 保留集或隐藏测试标签，也未改动融合系数或晋级门槛。小型 CSV/JSON 审计快照保存在 Git 忽略的 `outputs/`；[独立核对脚本](../audit_e28_fivefold_results.py)只产生[聚合 JSON](e28_qwen8b_fivefold_audit_aggregate.json)，不发布逐行预测或权重。

## 协议、数据与产物核验

- 服务器 `protocol_lock.json` SHA-256 为 `63f452e78d16b72ed111edde846f78e08ad827f2a705c385d0d23d134e2401e0`；其中配置、训练脚本和资源脚本哈希均与本地锁定文件**逐字节相同**。服务器锁与早期 Windows 预检锁的文件哈希不同，但内容字段相同，差异来自文件序列化/换行，未见训练超参或晋级规则变更。资源报告哈希、E0 manifest/OOF、E24 固定对照及五路组成分数哈希也全部匹配锁。
- 五个折文件各有 **432 个唯一 ID、24 个验证 prompt**；合并后恰覆盖原 E0 开发 OOF 的 **2,160 个 ID、120 个 prompt、18 类各 120 条**，没有重复、缺失或额外行。每折验证 prompt 与其他折互斥，行 ID、真实标签和折号逐项等于 E0 保存的分组；五折汇总文件与这五份折文件按原顺序拼接完全相同。代码与各折元数据记录每折只用另外 **96 prompt、1,728 行**训练，验证 432 行仅在末轮推理。没有额外的逐训练步数据清单，因此训练侧隔离由锁定代码、输入哈希及折元数据共同支持。
- 五折均记录 seed 42、固定模型文件哈希、同一 GPU 身份、固定包版本、**3 epoch 完成**、未按验证结果选 epoch/阈值、`holdout_evaluated=false`。每折 648 次计划优化器更新中完成 644 次、跳过 4 次，约 **99.38%** 成功。独立核对了各折 OOF 文件哈希、18 类有限 logits、保存预测与 logits argmax、逐折/逐类表和混淆矩阵；无不一致。
- 用锁定的 E24 E0c、RoBERTa 和三 seed ModernBERT 分数重算原固定融合，**2,160 个预测全部等于归档 E24 OOF**，balanced accuracy 为 **0.425000**。再按唯一预定的 1.0 权重加 E28 分数；未拟合或扫描融合权重。
