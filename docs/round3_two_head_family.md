# 第三轮：独立家族头实验（已完成）

## 假设与对照

固定六个家族：GPT（5 个精确标签）、Gemini（4）、Claude（5）、Qwen（1）、GLM（2）、Kimi（1）。在原 RoBERTa 的共享编码器和 18 类线性头之外，增加一个**独立的 6 类线性头**。两头读入同一次平均池化和 dropout 后的表示，训练损失固定为

`L = CE_18(逆频率类权重) + 0.2 × CE_6(无类权重)`。

推理和比赛评分仍只使用 18 类头的 logits。6 类头用于辅助监督及单独诊断，不参与硬门控或分数融合。这不同于 E13：E13 从同一 18 类 logits 对各家族做 `logsumexp`，没有独立的参数和输出头。本实验只检验该结构在相同训练日程下能否改善**精确 18 类**识别；家族头自身准确率不能作为晋级依据。

对照为 E2d-R 单头 RoBERTa 与 E10 的 E0c＋E2d-R 固定逐行标准化等权融合。保持 `FacebookAI/roberta-base` revision `e2da8e2f811d1448a5b465c236feacd80ffbac7b`、原 120 个开发 prompt 的五折划分、seed 42、12 epochs、256 tokens、batch 16、mean pooling、dropout 0.1、编码器学习率 `2e-5`、两个头学习率 `1e-3`、AdamW、10% warmup 和固定末轮评估。30 个已使用一次的保留 prompt 未用于训练、分词、评分或选模。新头在 18 类头之后初始化，默认关闭时模型输出和 checkpoint 参数名称不变。

## 预定评价

训练脚本输出原格式的 `oof_predictions.csv`（18 类分数），另输出 `family_head_oof.csv`（独立家族头分数）及各折、总体的家族头准确率。比较前核对训练数据、划分文件及 E0 OOF 的 SHA-256，并要求 E0c、E2d-R、新模型在 `id,prompt_id,true_model,fold` 上逐行一致；用旧两路分数精确重现已保存的 E10 OOF 预测。只在这之后比较新单模型与 E2d-R、E0c＋新模型与 E10 的 18 类 balanced accuracy、五折分数、逐类召回、叶头家族正确率及家族正确条件下的精确版本正确率，并以 prompt 为单位做配对 bootstrap。E13 的旧 `logsumexp` 结果只用于解释差异，不改动它的输出。所有融合权重保持 E10 原规则，不依本轮 OOF 搜索。

若 18 类主指标和固定融合没有稳定改善，或只是家族正确率上升而家族内版本识别下降，则停止这条路线，不更新全量推理包或 Kaggle 提交。已有多个开发集实验，任何小幅增益仍须视为探索性结果。

训练在物理 GPU 1（RTX 3090）完成，用时 559 秒；GPU 2 上的其他实验未受占用。服务器原始 `run_finetune_encoder.py` 与仓库基线 SHA-256 都是 `348c45c403dbf7f70941ad60b27e85d0b6125d8159ad1f911c8d09f07a1ce806`，E13 原脚本 SHA-256 为 `7b18a8dcc9d4dbc4ad56e03bf7f9199539fd1b0002949b6ece54a5a16b48e6e1`，两者未被覆盖。本地修改版以独立文件名 `run_finetune_encoder_two_head.py` 上传，SHA-256 两端一致，均为 `f75ee46b692d3698a204f41147c438a22c0c2e7c5407137ad1542b4197e82719`。训练前的 16 条开发样本烟雾检查验证了 18/6 输出、18 类推理输出一致性和两头有限梯度；默认 AMP 初始放大倍率在烟雾检查中出现梯度溢出，用低初始倍率复检通过，正式训练保留原动态 GradScaler 和跳步记录。预训练实际 revision 与指定 SHA 相同，训练/划分/E0 OOF 哈希与 E2d-R 一致。未保存折权重，因此本次只提供 OOF 比较，不是可直接推理的全量包。

## 运行命令（已执行）

当时使用物理 GPU 1、空输出目录运行。历史独立文件 `run_finetune_encoder_two_head.py` 未包含在公开仓库中；相同的 `--independent-family-head` 与 `--family-loss-weight` 选项已收录于公开的 `run_finetune_encoder.py`，可按下列命令重新训练。历史运行的精确源码文件及环境未归档，不能保证逐位复现原 OOF。

```bash
CUDA_VISIBLE_DEVICES=1 python run_finetune_encoder.py \
  --model-id FacebookAI/roberta-base \
  --revision e2da8e2f811d1448a5b465c236feacd80ffbac7b \
  --epochs 12 --pooling mean --max-length 256 --batch-size 16 --seed 42 \
  --family-loss-weight 0.2 --independent-family-head \
  --no-save-checkpoints --output-dir outputs/round3_roberta_independent_family_02
```

取消 `--independent-family-head` 且保留 `--family-loss-weight 0.2` 会复现 E13 的同 logits 家族损失；两个选项都不加则走原单头 CE 路径。输出配置记录 `family_loss_mode=independent_6_class_head`，避免把本实验误记为 E13。

服务器和本地 Git 忽略目录 `outputs/round3_roberta_independent_family_02/` 均保存本次 OOF、独立家族头 OOF、配置和指标。18 类 OOF SHA-256 为 `e27c5f63715902f8fc4c5fe9f7c2b335285699f7e8e65d32796f9e65b0857b42`，家族头 OOF 为 `deb605b2458696e8ff4b4c5917c639fe4d578bf654a4040f2e4a1f48f12c027a`；两端一致。`comparison_two_head.json` 和 `class_metrics_full.csv` 为核对后的结果表。复用的 `analyze_family_aux.py` 原始输出沿用 E13 的 `experiment` 字段名，专用 `comparison_two_head.json` 已明确标为独立双头实验；数值和配对区间一致。
