## 叠加规则

1. 先保存并对齐每条开发集回答的 18 类 OOF 分数、真值、`prompt_id` 和折号。独立分支不能读取同一折验证标签来训练分支本身。
2. 对便宜且已能运行的两项，做四格固定对照：E24；E24+E26 shape；E24+E25-B；E24+E26 shape+E25-B。后三项均复用固定逐行 z 标准化和等权融合，不依结果调权重。
3. 分阶段解冻是 **替代的训练配方**，不能当成已经训练好的分数路直接叠加。若要判断它与外部数据是否有交互，比较“官方/外部数据 × 全量微调/分阶段解冻”的四格；现有 E15 与 E25-B 是其中两格。
4. LoRA 和来源条件似然是潜在的新分数路。只在各自 OOF 显示互补、资源合格后，检验与当前最佳方案的固定组合；需要拟合融合权重时，必须在外层验证折以外的 prompt 上训练权重。
5. 新候选沿用建议筛选门槛：相对当时最强固定融合 BA 至少 +0.01、至少 4/5 折不降、任一类召回不下降 0.05 或以上，并报告按 prompt 配对的区间。多个候选连续筛选会使 OOF 乐观；Kaggle 公榜只用于少量外部核验，不用于反复调参。

## 资源与数据约束

- 2026-11-10 E25 seed 17 运行时，GPU 2 RTX 3090 的利用率约 95%；GPU 1 RTX 3090 约 3 MiB、0%，可容纳独立作业；GPU 0 有约 2.4 GiB 常驻占用、利用率 0%，启动前应确认来源。同一 GPU 上的训练不并发。容器有 32 个 CPU 核、约 232 GiB 可用内存。
- E24 外部来源只覆盖 17 类，`qwen3.8-max` 缺可核实精确快照。Open Pool v15 的主文件曾依赖全部官方训练行/提示选源，不能直接纳入严格五折。
- 官方测试没有 `prompt_id`；涉及同题中心化或标签分配的推理方案必须先验证能在实际测试输入结构下运行，不能假定每题 18 类各一条。
