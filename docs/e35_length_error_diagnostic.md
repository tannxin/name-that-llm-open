# E35：开发集长度与 E24 错误的低成本诊断

日期：2026-11-10。目标是判断是否立即投入 GPU 做原 [E5 三视图设想](experiment_plan.md)（全文、全文加开头、全文加等长其他片段）。本轮**只做已存五折 OOF 的事后诊断**，不训练、不选新截断阈值，也不使用官方保留的 30 个 prompt 或隐藏测试标签。可复算脚本为 [analyze_e35_length_diagnostic.py](../analyze_e35_length_diagnostic.py)，仅输出[公开安全的聚合 JSON](e35_length_error_aggregate.json)，没有逐行预测、提示或回答正文。

## 数据与核对

以 E0 固定 manifest 中的 120 个开发 prompt 为准。脚本流式读取官方训练 CSV，遇到非开发 prompt 立即跳过，随后才访问该行的回答文本与标签；只保留 **2,160 行、每类 120 行**。字符数为原始文本字符数，词数为空白分词数。256-token 标记来自 E19 已保存的开发集逐行长度，使用 [E9 审计](e9_length_ablation.md)固定 RoBERTa tokenizer（计特殊 token，`tokenizer.json` SHA-256 `847bbeab6174d66a88898f729d52fa8d355fafe1bea101cf960dd404581df70e`）；本轮未下载或安装分词器。逐行词数与原文重新计算完全一致，>256 的总数、逐折和逐类计数也复现 E9 的记录（合计 **256 行**）。

E24 预测来自已存 `outputs/e24_prvsiyan_analysis/oof_predictions.csv`。为分析分数间隔，脚本按原固定规则重算：E24 E0c、RoBERTa 各自逐行标准化，三个 ModernBERT seed 的逐行标准化分数先求平均，然后三路相加。重算的 **2,160 个 argmax 与保存的 E24 融合预测完全一致**。数据与分数文件的 SHA-256 均在聚合 JSON。E24 正确 **918/2,160 = 0.4250**；各类开发行数相等，故总体正确率等于本集 balanced accuracy。分数间隔是融合后第一与第二名之差，**不是校准概率**。

## 长度与错误

| 按原文长度分层 | 行数 | E24 正确率 | 分层内宏平均召回 |
| --- | ---: | ---: | ---: |
| 词数第 1 四分位：36–64 | 543 | 0.3315 | 0.3290 |
| 第 2 四分位：65–102 | 546 | 0.4231 | 0.4176 |
| 第 3 四分位：103–157 | 533 | 0.4447 | 0.4417 |
| 第 4 四分位：158–274 | 538 | 0.5019 | 0.4908 |

字符数按长度本身划出的四分位，正确率依次为 **0.3376、0.4015、0.4685、0.4926**（边界 431、670.5、1024.5 字符）。这两种原文尺度均呈“更长、更易识别”的描述性趋势；四分位只由长度决定，没有按 OOF 正误调边界。

| RoBERTa 精确 token 数 | 行数 / prompt | E24 正确率 | 分层内宏平均召回 | E24 相对旧 E16 正确率增量 |
| --- | ---: | ---: | ---: | ---: |
| ≤256 | 1,904 / 120 | 0.4107 | 0.4104 | +0.0163 |
| >256 | 256 / 111 | **0.5313** | **0.5036** | +0.0117 |

长回答占 **11.85%**，其中 120 条仍判错。长减短的正确率为 **+0.1205**；按 120 个 prompt 成组重采样 5,000 次、seed 42 的描述性 95% 区间为 **[+0.0574,+0.1848]**。按类别先求召回再平均，长减短仍为 **+0.0933**，相应 prompt 重采样区间 **[+0.0406,+0.1478]**。18 类中 11 类长文召回较高，7 类较低；每类长文仅 9–22 条，逐类差异不稳。五折各自的长文正确率均高于短文，折内差值为 +0.0577 至 +0.2263。

111 个 prompt 同时有长短回答；逐 prompt 等权的长减短正确率平均 **+0.1481**，62 个 prompt 为正、45 个为负、4 个相等。但每个 prompt 最多只有 6 条长文，因此这个配对描述仍会受类别与生成长度差异影响，**不能解释为截断使模型更准**。各类长文数、逐折指标和输入哈希见聚合 JSON。

融合分数的第一/第二名间隔中位数：长文 **0.994**，短文 **0.877**；在判错行中，长/短文分别为 **0.695/0.700**。以所有行间隔的无标签第 75 百分位作为描述性高间隔组，长文高间隔误判 **13/256**，短文 **167/1,904**。目前没有看到长文错误特别集中于高间隔、难以纠正的预测。

## 对 E5 的决定

**当前 E24 体系上不启动 E5 三视图 GPU 训练。** 256-token 截断只触及约 12% 的开发回答；这组在原文长度、类别平均和 prompt 分组描述中都没有较高错误率。E24 相对 E16 的收益也没有集中在截断组。已有 [E9 512-token RoBERTa 消融](e9_length_ablation.md)完全消除了该骨干的开发集截断，单路 BA 仅 +0.0009，固定 z-score 融合反而 −0.0023；[E19 连续句窗训练](round3_crop_results.md)亦未通过预设晋级条件。三视图不等同于上述两项实验，故这只是对**现在是否投入 GPU**的 no-go，而非证明所有长文视图都无效。

如新骨干实际 tokenizer 的截断情况与 RoBERTa 明显不同，应先在其**独立保存的 OOF**上重新做同样的长度与错误审计，再决定是否为该骨干预登记三视图单因素实验。本诊断使用反复开发过的 OOF，E24 外部来源生成协议也参考过完整官方训练长度分布；所有区间和分层均是探索性关联，不能作为独立测试收益或因果结论。
